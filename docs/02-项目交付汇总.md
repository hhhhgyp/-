## 5. 关键设计决策（实现必须遵守）

### 5.1 业务判定

- **状态**：`RESERVED / IN_USE / OVERDUE / COMPLETED / CANCELLED / EXPIRED / FORCE_CANCELLED`；占用类 = 前三个（`OCCUPYING_STATUSES`）。
- **终态**：`COMPLETED / CANCELLED / EXPIRED / FORCE_CANCELLED`（BR-34 不可再变更）。
- **柜格占用不落库**：由订单派生；派生优先级 `维护中 > 停用 > 柜体/寄存点不可用 > 使用中 > 已预约 > 可用`。
- **营业时间**约束的是 `start_time` / `end_time` 的**当日时刻**，不是整个占用区间（否则 72 小时上限无法成立）。
- **尺寸**：`SIZE_LEVEL_ORDER` 比较，允许大柜放小行李，禁止小柜放大行李。
- **支付**：`pay_status` 恒为 `UNPAID`，本期不接入支付，任何规则都不依赖它。

### 5.2 三项不可动摇的工程约定

1. **锁顺序**：任何需要同时持有两把锁的路径，先锁柜格行，再操作订单行。
2. **两防线**：柜格行 `SELECT … FOR UPDATE` + `uk_slots_cabinet_slot` 唯一索引；正确性不依赖隔离级别。
3. **条件更新**：取消 / 签到 / 取件 / 强制取消 / 任务处理一律 `UPDATE … WHERE id=? AND status=?` + `rowcount`，不做「先读后写」。

### 5.3 错误码优先级（测试必须按此断言）

| 场景 | 优先级 |
|---|---|
| R1 创建 | BR-07 件数 → BR-01 对齐 → BR-02 时长 → BR-03 过早 → BR-04 超前 → 幂等重放 → 404 不存在 → BR-09 柜格 → BR-11 寄存点 → BR-10 柜体 → BR-12 规格 → BR-08 尺寸 → BR-05 营业时间 → BR-13 冲突 |
| R4 取消 | 404 → 403 → 409 状态 → 409 取消窗口 |
| R5 签到 | 404 → 403 → 409 状态 → 409 签到窗口 |
| R6 取件 | 404 → 403 → 409 状态 |
| M11 强制取消 | 404 → 409 终态（`reason` 缺失由请求模型先拦，400） |

> 同一请求同时违反多条时，以表中靠前者为准。参数校验失败统一 **400 `VALIDATION_ERROR`**（不是 FastAPI 默认的 422）。

## 8. 未实现与已知边界

| 项 | 说明 |
|---|---|
| 支付 | `pay_status` 恒为 `UNPAID`，无支付/退款接口 |
| 多件行李 | `luggage_count > 1` → 400 `MULTI_LUGGAGE_NOT_SUPPORTED` |

| 分布式调度 | 不支持；调度器在进程内，必须 `workers=1` |
| 改营业时间/尺寸/价格 | 不对历史订单回溯校验，金额与名称用下单快照 |
| `release_job_interval_seconds` | 只在启动时读取一次，修改需重启 |
| 生产安全 | 开发默认 `JWT_SECRET_KEY`、`DEBUG=true`，启动会告警 |
